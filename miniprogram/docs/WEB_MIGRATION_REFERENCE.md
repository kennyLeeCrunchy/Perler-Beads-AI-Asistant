# Web 与小程序迁移差异

更新时间：2026-09-05

## 唯一来源

`APP/frontend` 是 Web 前端的唯一源码。小程序目录不再保存 Web 快照；迁移时按本表把当前 Web 行为改写成 Taro/微信能力，并以接口类型和自动化测试校验一致性。

## 产品能力差异

| 能力 | Web | 小程序正式版 |
|---|---|---|
| 上传图片转图纸 | 保留 | 保留 |
| 图纸前 image-to-image 清稿 | 保留 | 保留 |
| 52/78/104 三档结果选择 | 保留 | 保留 |
| AI 文生图 | 保留完整服务 | 因 Token/调用成本关闭，不提供入口 |
| 编辑、制作辅助、导出 | 保留 | 保留并适配触摸与相册 |
| 本地作品 | 浏览器存储可作降级 | Taro Storage 只作草稿/离线降级 |
| 云端作品 | 待作品 API | 待作品 API、OpenID 和对象存储 |

## 技术替换

| Web 实现 | 小程序实现 |
|---|---|
| `react-router-dom` | `app.config.ts` 页面声明与 Taro 导航 API |
| DOM、CSS Grid、鼠标事件 | Taro 组件；大图纸使用 Canvas、触摸和平移缩放 |
| `fetch`、`FormData` | `Taro.request`、`Taro.uploadFile` 或云托管调用 |
| `Blob` 与浏览器下载 | 临时文件、下载文件、保存到相册 |
| `localStorage` | `Taro.getStorageSync`；正式数据迁往云端 CRUD |
| Web 顶部导航 | 原生页面导航和 `tabBar` |
| px 与浏览器媒体查询 | rpx、安全区和真机断点验证 |

## 当前落差

| 模块 | 当前状态 | 后续工作 |
|---|---|---|
| 页面骨架 | 首页、转图、预览、编辑、作品、制作、设置、隐私已存在 | 逐页按正式交互验收 |
| 转图 | 已调用 `POST /api/pattern/generate` | 接入图纸前清稿和一次生成三档结果 |
| 作品 | 本地存储可用 | 增加账号、作品 CRUD 和对象存储 |
| 编辑器 | 已有基础编辑页 | 验证 78/104 大图、触摸、撤销和局部重绘性能 |
| 制作辅助 | 已有基础页面 | 移除固定编号/区域等可能误导的占位逻辑 |
| 导出 | 仍需完整闭环 | 对齐色号、镜像、分区、相册和失败状态 |
| AI 文生图 | 不应迁移 | 入口、路由和调用保持不存在 |
| 图纸前 AI 清稿 | 尚未接入 | 后端能力开关、超时/失败降级、额度与内容安全 |

## 不可回归约束

1. 小程序不得因为 Web 保留文生图而重新出现文生图入口。
2. AI 清稿失败不能阻断直接转图纸。
3. 三档图纸必须来自同一份清稿结果，不能为每个尺寸重复调用模型。
4. Web 的 Logo、路由和功能调整不通过复制源码同步；只通过文档、共享类型或接口契约同步。
5. 任何演示按钮进入正式版本前必须有真实行为、明确禁用态或被移除。
