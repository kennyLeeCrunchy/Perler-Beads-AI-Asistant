# 拼豆图纸算法说明

本文档说明 demo 当前采用的图片处理和颜色转换流程，重点解释透明底处理、颜色量化、暗色细节保护，以及后续可升级的 CV/主体分割方案。

## 1. 文档定位

这份文档属于开发文档/技术方案，不是 PRD 主体。

PRD 应该描述用户价值、交互入口、业务规则、验收标准和失败提示。例如：

- 用户勾选“透明底/不规则图形”后，背景不参与填色。
- 系统不信任 AI 直接生成透明底。
- 透明处理失败时要提示用户重新生成干净主体图。
- 色号统计只统计主体区域。

具体算法细节，例如阈值、flood fill、mask 质量门、mode-pool、暗色细节保护、OpenCV 或分割模型选型，建议放在本文档这类开发文档中维护。

## 2. 当前设计原则

透明底能力采用零信任策略：

- 不假设生图模型能稳定输出真实 alpha 透明 PNG。
- 不把灰白棋盘格当作透明底。
- 不把 RGBA 文件本身视为处理成功，必须检查 mask 质量。
- 透明区域必须由系统生成、验证，并在转图纸阶段从颜色统计中排除。

颜色转换采用“两阶段”策略：

- 先用稳定的主色块算法生成大面积色区。
- 再用细节保护算法补回眼睛、鼻子、嘴巴、描边等小面积深色特征。

这样做是因为拼豆图纸既要色块稳定，也要保留角色表情和轮廓。只做多数投票会让主体更干净，但容易吃掉细线；只做细节优先又会产生噪点。

## 3. 当前透明底处理流程

当前透明底处理代码位于：

```text
app/core/mask_processor.py
```

透明底/不规则图形模式下，生图 prompt 要求模型生成：

- 纯白背景 `#FFFFFF`
- 单主体
- 扁平卡通/插画风格
- 无灰白棋盘格
- 无阴影
- 无 3D 成品照片感
- 无珠子实物纹理

系统随后执行透明底后处理：

1. 如果图片已有有效 alpha 通道，读取 alpha 作为前景 mask。
2. 如果没有 alpha，识别从图片边缘连通的浅色/近白背景。
3. 将背景区域 alpha 设为 0，主体区域 alpha 保持 255。
4. 计算前景占比。
5. 如果前景占比超过质量阈值，判定 mask 失败。

当前 demo 的质量门：

```text
foreground_ratio > 0.75 => mask failed
```

这个规则用来阻止假透明背景继续进入图纸流程。例如 AI 画出了棋盘格背景、投影、成品挂饰照片时，简单 mask 可能只能抠除少量边缘；这时系统必须报错，而不是假装已经生成透明底。

## 4. 当前图纸颜色转换流程

核心入口是：

```python
quantize_image(...)
```

代码位于：

```text
app/core/quantizer.py
```

主要步骤如下：

```text
前景 mask
→ 图像预处理
→ 选择 Artkal 子色板
→ 4x LANCZOS 缩放
→ PIL 调色板量化
→ 4x4 mode-pool 回目标网格
→ 稀有色清理
→ 相似色合并
→ 最大颜色数限制
→ 边缘平滑
→ 暗色细节保护
```

### 4.1 前景 mask

如果开启 `remove_bg`：

1. 优先使用图片 alpha 通道生成 cell mask。
2. 如果没有 alpha，则用浅色背景检测生成 cell mask。
3. mask 外区域会被标记为空白格 `None`。

空白格不参与颜色量化、色号编号、色号统计、材料数量统计。

### 4.2 4x 中间图与 mode-pool

系统先把原图缩放到目标图纸的 4 倍尺寸：

```text
target grid: 48 x 48
intermediate image: 192 x 192
```

这样每个最终豆格对应一个 `4 x 4` 的采样块。

每个最终豆格取对应 `4 x 4` 采样块里出现最多的颜色。这个步骤适合处理大面积色块，例如身体、脸部、耳朵、肚皮等区域。它能减少噪点，让图纸更稳定。

但它有一个问题：细线容易丢。例如嘴巴是一条黑线，可能只占某个豆格中 16 个采样点里的 1-3 个点。白色脸部占比更高时，多数投票会把该格变成白色，黑色嘴巴就消失了。

## 5. 暗色细节保护

为了解决眼睛、鼻子、嘴巴、描边丢失的问题，系统增加了“暗色细节保护”。

位置：

```python
_build_dark_detail_codes(...)
_apply_detail_codes(...)
```

处理逻辑：

1. 在 4x 中间图上检测近黑像素。
2. 对每个最终豆格计算近黑像素覆盖率。
3. 如果覆盖率超过阈值，记录这个格子的深色候选。
4. 先走正常量化、相似色合并、颜色数限制、边缘平滑。
5. 最后再把暗色细节覆盖回图纸。

当前阈值：

```text
min_coverage = 0.08
```

也就是一个豆格里只要有约 8% 的采样点是近黑像素，就认为这里可能是表情线、鼻子、眼睛或描边。

细节保护必须放在最后。如果先保护黑色，再执行边缘平滑，平滑算法会把孤立黑格当成噪点重新替换掉。

## 6. 当前限制

当前轻量方案适合纯白底或近白底、单主体、主体边缘清晰、扁平卡通/插画风、大色块图案。

当前轻量方案不适合复杂背景、假透明棋盘格、明显投影、3D 成品挂饰照片、珠子实物纹理照片、主体和背景颜色过于接近的图片。

暗色细节保护只解决近黑细节，包括眼睛、鼻子、嘴巴、黑色描边、深色小装饰。它不解决所有细节问题，例如红色腮红、浅色高光、彩色小花纹仍可能被多数投票合并。

## 7. 后续优化：OpenCV 传统 CV 方案

当前 demo 用的是 `Pillow + NumPy` 实现轻量 CV。后续如果要增强稳定性，可以引入 OpenCV，把透明底处理升级为更完整的传统 CV pipeline。

建议流程：

```text
1. 读取图片
2. 如果已有有效 alpha，直接使用 alpha mask
3. 如果没有 alpha：
   - 转 HSV / Lab 色彩空间
   - 从四边和四角估计背景色
   - 用亮度、饱和度、色差阈值识别背景候选区
   - 从边缘 flood fill，只移除与边缘连通的背景
4. mask 后处理：
   - morphology open 去除小噪点
   - morphology close 填补小裂缝
   - fill holes 填补主体内部孔洞
   - connected components 保留主体主连通区域
   - dilate 1-2px 轻微外扩，减少白边
5. 输出 RGBA 透明图
6. 通过质量门：
   - 前景占比过高，失败
   - 主体太小，失败
   - 边缘残留背景过多，失败
```

OpenCV 可用能力：

```python
cv2.cvtColor(...)
cv2.inRange(...)
cv2.floodFill(...)
cv2.morphologyEx(..., cv2.MORPH_OPEN)
cv2.morphologyEx(..., cv2.MORPH_CLOSE)
cv2.connectedComponentsWithStats(...)
cv2.dilate(...)
```

传统 CV 的优点是速度快、不需要模型推理、可解释、可调参，对纯白底/近白底主体图很稳定。

传统 CV 的限制是遇到阴影、棋盘格、复杂背景会不稳定；主体和背景颜色接近时容易误抠；它不能理解“主体是什么”，只能根据颜色和连通性判断。

因此，传统 CV 适合作为第一层快速路径，不适合作为唯一兜底。

## 8. 后续优化：主体分割/抠图模型兜底

如果传统 CV 质量门失败，后续可以接入主体分割或抠图模型作为第二层兜底。

候选路线：

- `rembg / U2Net`
- `MODNet` 或其他 matting 模型
- `SAM` 类主体分割模型
- 云端图片主体分割 API

推荐产品级流程：

```text
AI 生图
→ 零信任检查
→ 传统 CV 快速抠图
→ CV 质量门
→ 如果失败，进入主体分割模型
→ 分割质量门
→ 如果仍失败，提示用户重新生成干净主体图
```

模型兜底成功后仍然需要做 mask 后处理：去噪、填洞、边缘平滑、边缘轻微膨胀、alpha threshold、前景占比检查。

模型兜底的优点是能理解主体，复杂背景下更稳，对非纯白背景更友好。限制是会增加依赖和部署复杂度、增加推理成本，速度慢于传统 CV，并且仍需要质量门。

## 9. 后续优化：颜色转换能力

颜色转换后续可继续增强：

- 高饱和小色块保护，避免腮红、小装饰被吞掉。
- 用户可调的细节保护强度。
- 局部编辑/手动补点。
- 专门的人脸/表情区域保护。
- 颜色区域连通性优化，减少孤立色块。
- 对白色主体内部区域做保护，避免被误当背景。

其中“暗色细节保护”已经解决眼睛、鼻子、嘴巴、黑色描边这类近黑细节。彩色小细节还需要新的保护策略。

## 10. 判断效果时看什么

调试一张图纸时，建议依次检查：

1. 源图是不是干净主体图。
2. 透明处理图是否真的有 alpha。
3. mask 是否通过质量门。
4. 背景是否还进入色号统计。
5. 主体大色块是否稳定。
6. 眼睛、鼻子、嘴巴、描边是否被保留。
7. 相似色合并是否过强，导致需要保留的颜色被吞掉。

如果黑色嘴巴消失，优先检查暗色细节保护。

如果背景进入统计，优先检查 mask。

如果主体内部颜色过碎，优先检查相似色合并和最大颜色数。
